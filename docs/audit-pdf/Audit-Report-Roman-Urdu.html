2. Tareeqa

  • 37 invariants (SQL rules): jaise "item ka stock = batches ka jor", "lot outward = SO cards + wapas", "packing list = Folding ka bheja hua". Har test ke baad aur live DB par chalaye.
  • Shadow model: random operations ko alag FIFO model se muqabla (12 seeds x 160 qadam).
  • Scenarios: costing 12, kapra 21, mushkil flows 3, concurrency 12, reports ka mel 5, security 8 (1,803 GET/DELETE calls + 60+ valid hamle), kharab input (8,986 calls), super admin (1,485 calls), audit log (54 calls), time zone, extremes, Urdu/emoji, speed.
  • Total: 36 suites, 182 tests: 181 pass, 1 skip (speed), 0 fail. Aik test.failing baqi (AUD-04).

4. Jo cheezein theek nikli

  • Stock/value hamesha batches ke jor ke barabar; negative kabhi nahi; ledger match.
  • Average rate aur batch costing: 20 kg @40 + 100 kg @45, 30 kg issue = Rs 1250 (800+450).
  • Return usi rate par; rework loop mein cost sirf ek baar; cost bantwara 5 jagahon par ek jaisa.
  • Concurrency: 8 SO cards ek lot se ek waqt mein, bilkul 3 kamyab; numbering mein duplicate nahi.
  • Passwords bcrypt 12 rounds; npm audit 0 vulnerabilities; git mein secrets nahi; SQL injection safe.
  • Audit log immutable; 40 migrations ulti/seedhi chalti hain.

5. Baqi kaam aur faisle

  1. AUD-04: Folding mein kitna gain/loss theek hai (jaise 5%)? Us se zyada par rok ya approval?
  2. Migration 20261021000001 live DB par abhi nahi chali: npm run db:migrate, backup ke saath.
  3. Production .env: JWT secrets 32+ characters, login lock 15 minute, nginx ke peeche.
  4. Frontend ko 5 jagah react karna hai (guide: docs/frontend/audit-fixes.md).
